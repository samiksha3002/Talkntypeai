## M5: persistent, private bookmarks

Confirmed original defects: routes/saved.js uses a module-level Map keyed only by docid; all clients share it, there is no verified owner, and a process restart loses entries. The frontend bookmark API sends no authentication. useSaved hides list failures, and the page's async save handler can reject without displaying an appropriate failure.

The new dedicated SavedJudgement Mongo model stores ownerId, docid, title, citation, court, date and savedAt. The owner comes exclusively from H1's requireDraftAuth middleware, which checks the bearer-session hash, expiry and current account access. Body userId/ownerId/_id values are rejected. The same account subscription/admin eligibility policy as H1 applies; no new authentication bypass or static-admin exception exists.

Every list, upsert and delete query is owner-scoped. A compound unique ownerId/docid index and a deterministic SHA-256 owner/document _id prevent duplicate creation even before a unique secondary index is built. Atomic upsert plus duplicate-key recovery handles concurrent retries. Duplicate POST retains the existing entry and savedAt rather than creating or unexpectedly overwriting metadata. List sorting is deterministic. Dates and document IDs remain strings in responses; numeric judgement IDs are normalized to strings. Returned fields preserve existing contracts: GET {saved:[...]}, POST entry with HTTP 201, DELETE {message}; owner/internal IDs are never returned. Missing deletes return 404; DB failures return safe 503 JSON and no false success. Responses use no-store.

The bookmark client sends the existing secure session token only to the explicitly configured H1 Express origin, with timeout, cancellation and redirect rejection. Missing/blocked session storage fails closed. It checks that the session did not change while a response was in flight. The hook isolates cached rows by session identity, discards stale responses, updates UI only after confirmed mutation, and exposes failures. The page provides saved-list navigation using original docid, retry/sign-in actions and disabled controls while loading/mutating. Search, preview, printing and headnote behavior are retained.

## M8: PDF and Word export

Confirmed original defects: EditorActions.jsx flattens HTML through textContent and writes all PDF lines to one jsPDF page using Helvetica; paragraph breaks/formatting and non-Latin rendering are lost and long content clips. Word maps each Delta operation to a new paragraph, so inline formatting boundaries become block breaks, while newline-only operations are mishandled. It also uses the wrong italic property and treats pixel size values as points.

The Delta parser accumulates inline runs and closes paragraphs only on actual newline characters, applying the newline operation's block attributes. Empty lines survive and the required terminal Quill newline does not create an extra phantom paragraph. Export snapshots do not modify Quill or manualText. It maps Quill font tokens and px/pt sizes explicitly. Export libraries load on demand; download names remain document.pdf and document.docx. The existing Save menu stays in place, export clicks are serialized, progress/failures are visible, and failure does not download a partial file. The unrelated Print/OCR/speech/import actions are unchanged.

Word uses actual DOCX paragraph/run structure: inline bold/italic/underline/strike, complex-script bold/italic, font sizes, text colors/backgrounds, headings, alignment, ordered/bullet numbering and indentation. It sets A4 dimensions and margins and leaves pagination to the Word processor; no fixed-height text boxes clip content. Unicode remains original text in XML. Fonts are referenced by name, not embedded; Nirmala UI is the complex-script preference, with viewer font substitution if unavailable. Existing legacy-font users still need the corresponding legally licensed fonts installed in their Word environment.

PDF constructs safe text-only DOM from the same block model, waits for fonts, measures grapheme/line bounds, and allocates complete visual lines across A4 pages. It handles paragraphs larger than a page rather than clipping a whole paragraph. Each page is rasterized separately at scale 2, then discarded, avoiding one giant whole-document canvas. Browser layout performs Devanagari shaping and mixed-script rendering using existing/system fonts. A separate blank Type3 font with ToUnicode line mappings supplies original Unicode for PDF search/copy without embedding or redistributing a proprietary font binary. Complete-line mappings avoid PDF viewer spacing heuristics corrupting Devanagari words. No H3 conversion function or mapping is called or changed.

### M8 limitations and risks

- PDF is browser-rasterized visual content plus a searchable Unicode text layer, not a vector-text or PDF/A/tagged accessible export. Selection highlighting is line-wide. Actual manual viewer search/copy across Acrobat, Chrome and other viewers still needs acceptance testing. Soft wrapping can introduce ordinary copy/paste line breaks. Complex-script shaping depends on fonts available to the browser; no new font binary or license was obtained or redistributed.
- Headings, margins, spacing and list layout use a normalized A4 export style, not a pixel-identical reproduction of Quill's screen layout. PDF and Word page counts can differ because Word lays out its own fonts. DOCX visual rendering in Microsoft Word/LibreOffice and its actual multipage page count were NOT executed; XML and content checks do not prove visual fidelity.
- Images/other Delta embeds, code blocks and blockquotes deliberately fail with a visible error rather than silently omitting content. Tables, tracked changes, footnotes, embedded objects and live hyperlink targets are not implemented; plain link text is retained. Existing print behavior is outside this patch.
- Legacy font byte text remains unchanged; it is not converted into Unicode by export. Confirm KrutiDev/Shivaji licensing and cross-device glyph appearance before relying on legacy-font output. Font substitution and very large-document memory/CPU consumption need target-device staging tests. Intl.Segmenter is required for PDF; unsupported browsers get a visible error.
- PDF page canvases are released sequentially, but measured DOM/glyph metadata, final PDF images and document bytes remain in browser memory. No claim is made for arbitrarily large files or low-memory mobile devices.
