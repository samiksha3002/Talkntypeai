## H2: dictation

Flow: Stenocard's Deepgram/Web Speech callbacks -> Sidebar callback -> Dashboard -> Editor -> Quill. Previously callbacks supplied separate strings, Dashboard replaced one string state value, and Editor suppressed equal text and subtracted matching prefixes as if speech were cumulative. A callback with multiple native final results handled only the first. Substring punctuation matching affected words such as semicolon. Finding any newline command replaced the whole utterance; automatic legal-word capitalization also changed dictated casing.

Provider adapters now emit identified, final utterance events. Deepgram uses channel/start/duration identity for duplicate final delivery; an explicit speech_final signal is supported when is_final is absent. Explicit interim results are ignored. Native recognition handles every changed final index and tracks it within that recognition session. Repeated words with distinct utterance identities remain distinct. Dashboard queues events with functional updates, so React batching cannot discard earlier finals. Editor acknowledges consumed IDs and does not subtract text prefixes.

Command matching uses complete Unicode word boundaries and longest phrases. Newline/paragraph commands preserve text on both sides; ordinary words/casing and literal punctuation are retained. Automatic punctuation immediately attached to a spoken punctuation command is used once. Both providers retain their existing language/options/transport. Last selection is remembered across microphone-button blur; text is inserted at that caret without deleting selected existing content, with current Quill formatting. Stop waits for the recorder's final data chunk before closing; native stop-time finals remain accepted until onend.

Compatibility/limitations: interim text is not previewed in the document. The existing command vocabulary remains active (saying a command literally will still invoke it). Deepgram events without a final signal are not guessed final. Provider metadata assumptions, actual device permissions, reconnects, pronunciation, and transcription quality require isolated staging/live-provider verification. Existing provider credential architecture is outside this patch and unchanged.

## H3: font conversion

Flow: FontConvertCard -> Dashboard command -> Editor's Quill snapshot -> existing POST /api/font/convert -> existing local conversion utilities -> new Delta. The old effect sent newline-only ops to an API that correctly rejects whitespace-only text.

A separate fontConversion helper preserves whitespace-only operations and their attributes without requests. Mixed text operations split only at paragraph separators; edge whitespace and every interior whitespace run are preserved, including tabs and NBSP. Matching meaningful runs share a cached request during that conversion. Embed values and inline/block attributes are copied. The API contract, validation, supported mapping registry and conversion algorithms remain unchanged.

Conversion is atomic: no editor write occurs until every response is valid. Errors, empty/newline-changing responses, changed word spacing, cancellation, or newer document edits retain the original/current document. Selection positions are mapped into the converted Delta, and the existing matching legacy font is applied. Reverse Unicode conversions clear the prior root legacy font.

Literal angle brackets are kept local during forward Unicode conversion so existing HTML preprocessing cannot consume plain Quill text as tags. Formatting that splits one Unicode grapheme across operations fails safely before any requests; keep that character's formatting together before retrying. Selection mapping within a length-changing run is approximate; run-boundary positions map exactly. This does not certify all linguistic mapping/font-glyph fidelity. Existing font assets are unchanged; Preeti availability remains environment-dependent. Large documents with many unique styled runs may still encounter the existing API rate limits; failed conversion does not partially replace the document.
