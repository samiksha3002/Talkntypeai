## H4: searchable PDF text

Confirmed cause: installed Tesseract recognize defaults to text output, while the old route reads data.words. Requesting blocks:true exposes words under blocks/paragraphs/lines/words. The old route also rasterizes all pages into memory and reconstructs every page from images.

Files: routes/searchablePdf.routes.js; utils/searchablePdf.js; tests/h4-pdf.test.mjs. H4 route admission/upload controls depend on the separate H5 resourceProtection utility.

The new utility requests supported word geometry, renders one source page at a time, maps coordinates through PDF.js viewport conversion (including page rotation/crop offsets), and adds invisible text to the original PDF pages. Original image resources, page boxes, order and rotation survive. Image inputs retain the previous 200 DPI sizing convention. Workers, canvases and PDF.js documents are released in finally blocks. The existing two paths, multipart field names, PDF response type and attachment name remain. An additive X-OCR-Word-Count header distinguishes blank OCR output.

Blank pages are valid and retained. Missing geometry for nonempty text, malformed boxes and worker failures fail the request instead of returning an apparently searchable PDF. Helvetica cannot encode Devanagari; unsupported text returns 422 with no partial PDF. No new Hindi/Marathi language support is claimed. Only English local resources are selected. OCR_LANG_PATH is now REQUIRED, pointing to a provisioned local eng.traineddata.gz, or eng.traineddata with OCR_UNCOMPRESSED=1. Automatic runtime model download is intentionally removed. This is a deployment prerequisite and a change from previous cold-start behavior.

Executed: 12 Node tests, 12 PASS / 0 FAIL. OCR recognition is mocked; actual PDF parsing, rasterization, generated text extraction and pixel comparison execute locally. Covers single image, multipage scan, rotations 0/90/180/270, crop offsets, dimensions/order, blank page, errors, abort, unsupported Hindi/Marathi and missing local OCR configuration. Pixel equality checks verify invisible overlays do not change the scan. Real Tesseract recognition, native OCR resource initialization and manual PDF search/selection in a viewer remain UNVERIFIED because no local language model is configured. Selection placement uses approximate font metrics and needs real-scan acceptance.

## H5: bounded expensive requests

Confirmed causes: unlimited OCR/CSV disk uploads, unlimited PDF memory uploads, missing PDF/image/row bounds, general rate limiter after JSON parsing, and Python read-all uploads and synchronous provider calls inside async handlers. Existing general per-IP limiter alone neither bounds active work nor authenticates callers.

Files: utils/resourceProtection.js; server.js; routes/ocr.js; routes/pdf.js; routes/csvUploadRoute.js; routes/searchablePdf.routes.js; routes/audio.js; routes/aiChat.js; routes/chatTranslate.js; routes/expand.js; routes/fixGrammar.js; routes/judgementAi.js; routes/legal.js; routes/legalaidraft.js; routes/transliteratefinal.js; TNT_BRAIN/resource_protection.py; TNT_BRAIN/server.py; tests/h5-resources.test.mjs; tests/h5_brain_test.py.

Node uploads now stream to private temporary files with bounded multipart fields/file count, cleanup on failure/abort, and signature/content validation. PDF and image validation runs before providers. CSV keeps existing column mapping and response shape; parsing has row/row-byte caps and stream errors are handled. CSV's existing client-supplied userId is retained for compatibility, NOT asserted as authentication. Existing unordered database writes can partially succeed; no migration or transactional import redesign is included.

Shared admission rejects excess concurrent jobs before uploads with 503 and Retry-After. Rate budgets return 429; file/body limits return 413; invalid types/content return 415/422. JSON errors retain error/success fields; successful OCR/PDF/CSV and transcription response shapes remain. General API limiting and bounded simultaneous JSON/form buffering precede parsing. Expensive AI routes share per-IP rate and process-local concurrency limits. Timed-out handlers keep their processing slot until underlying work settles; a timeout must not silently allow replacement work while CPU/provider operations continue. OpenAI OCR/transcription and Gemini PDF extraction also have SDK deadlines. Generic AI wrappers cannot forcibly stop every existing provider operation; stalled upstream calls can exhaust slots and require operational recovery.

Python ASGI middleware bounds actual body bytes (including chunked input) before multipart/JSON parsing, spools bodies to disk, and limits admission, rates and response duration. Uploads are copied in chunks, validated with installed PyMuPDF, closed, and partial files removed on failure. Synchronous document/provider calls move to the existing thread pool so admission timers can run. Streaming responses keep the slot through consumption. A timed-out SSE response closes, and underlying work retains its slot until completion; it does not emit a false DONE success. The client may require a retry. Full FastAPI/provider integration is not executed: importing server.py would load environment and instantiate providers. Tests execute only the extracted upload functions and the independent middleware.
